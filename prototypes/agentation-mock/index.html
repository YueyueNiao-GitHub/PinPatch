工作方式

  1. 在本地 HTML、localhost 或开发测试页面打开 PinPatch。
  2. 悬停并点击有问题的元素，写下希望如何修改。
  3. PinPatch 自动整理页面位置、元素信息和留言上下文。
  4. 复制单条或全部结构化留言，粘贴给当前使用的编码 Agent。
  5. Agent 处理后回到页面验收，确认解决或继续补充要求。

适用页面：PinPatch 面向正在开发和测试的项目页面，不用于普通互联网内容页面。

Agent 如何准确理解

PinPatch 不只记录一句留言，还会把“哪个页面、哪个元素、位于哪里、希望怎么改”一起整理出来， 帮助 Agent 更快落到目标代码上下文。

  • 页面信息说明问题出现在哪个本地或测试页面。
  • 元素定位记录选择器、组件线索和视觉位置。
  • 修改意图保留用户原始留言与后续补充要求。
  • 处理记录串联 Agent 的处理摘要和用户验收结果。

复制交付

PinPatch 将页面位置、元素信息、用户留言和可视化调整差异整理成结构化文本。 用户可以复制一条具体反馈，也可以一次复制当前页面的全部留言。

  • 复制单条适合只处理当前问题，并保留完整元素上下文。
  • 复制全部适合一次交付当前页面中的多个问题。
  • 适配任意 Agent不要求安装专属连接服务，也不限制用户使用的编码工具。

Agent 会收到什么

复制内容不只包含一句评论，还会尽可能保留问题出现的位置和用户希望达到的效果， 帮助 Agent 减少查找元素和反复确认的时间。

  • 页面与元素：页面地址、元素名称、选择器、视觉位置和源码线索。
  • 用户要求：自然语言留言、选中的文字和后续补充内容。
  • 样式上下文：当前样式详情以及可视化调整前后的差异。
  • 验收依据：用户希望看到的目标效果和需要继续确认的问题。

回到页面人工验收

PinPatch 1.0 不自动获取 Agent 的处理进度。用户将留言交给 Agent 后，需要回到页面检查实际修改结果， 再决定解决问题或继续补充要求。

  • 待处理：留言仍可编辑、补充、复制或删除。
  • 人工检查：用户刷新页面并对照原留言检查效果。
  • 继续补充：不符合预期时重新调整或再次复制留言。
  • 已解决：用户确认修改符合预期并主动关闭事项。
